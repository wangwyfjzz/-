# 麦麦遛娃助手（mcd-family-party）

> 麦当劳程序员创意开发大赛参赛作品 · 基于麦当劳 MCP 开发的亲子活动发现与派对预订技能

看周末亲子活动、办主题派对、订门店场次、查派对订单——带娃吃麦，一站搞定。

## 它解决什么问题

麦当劳的亲子活动信息是分散的：活动日历里只有标题和海报，积分商城里才有真正可下单的商品，而两者之间没有互相跳转的入口。家长想给娃办一场生日派对，通常要在两个地方来回切换，还未必知道哪家门店哪天哪个场次能约。

本技能把这两块拼起来：先用日历告诉你最近有什么亲子活动，再把可下单的商品、可约的城市、门店、日期与场次收敛成一条对话式预订漏斗，最后在下单前给你一张完整的确认单。全程不改写任何接口返回值，价格与档期一律以实时接口为准。

## 目标用户

3 至 12 岁儿童家庭，家长是决策与付费主体。客单价区间约 45 至 198 元，属于家庭计划型预付消费。典型诉求是「这周末带娃去哪玩」和「给孩子办个生日派对」。

## 核心能力

- **周末遛娃日历**：拉取营销活动日历，筛出亲子类活动，与商品池匹配后输出活动卡片（活动名、主题分类、价格、可约城市数、状态）。可预订判定采用状态与有效期双重条件：后端对已过下架时间的商品仍会返回上架状态，因此只有状态为上架或预热、且当前时间落在上架时间与下架时间之间，才被判定为可预订。匹配不上的条目降级为纯资讯卡片，不硬造可预订入口。
- **派对定制预订**：支持两条路径。想好了办什么，就按「活动类型 → 主题 → 版本」三步收敛；只想看看，就从日历卡片直接点选。两条路径在确定商品后汇入同一条漏斗：选城市 → 选门店 → 选日期 → 选场次 → 确认单 → 明确确认 → 下单。
- **版本对比卡**：同一主题的常规版与尊享版并排对比价格与权益，数据取自商品详情的 sku，不靠名称推断。
- **我的遛娃订单**：查询商城订单列表与详情，结合服务器时间对未来场次做临期提醒，并引导到麦当劳 App 查看入场凭证。

## 安装方法

前置条件：一个麦当劳中国 MCP 令牌。在麦当劳 MCP 开放平台完成手机号登录后，进入控制台激活并复制令牌。

将令牌写入环境变量，不要把令牌写进任何文件：

```bash
export MCD_MCP_TOKEN=你的令牌
```

在支持 MCP 的客户端中按下述配置接入，完整示例见仓库根目录的 mcp-config.example.json：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

把 mcd-family-party 目录放入客户端的技能目录后即可使用。技能脚本只需 Python 3 标准库，无需安装任何第三方包。

## 使用示例

- 这周末带娃去哪玩？—— 拉取当月活动日历，筛出亲子类活动并给出可预订卡片。
- 孩子 4 岁生日，想办个迪士尼主题的派对 —— 走定制路径，按类型、主题、版本收敛后进入预订漏斗。
- 想带娃去消防体验营 —— 定位到对应商品，确认可约城市后逐级选到门店、日期与场次。
- 过家家的常规版和尊享版有什么区别？—— 调商品详情取 sku 数据，生成价格与权益对比卡。
- 我订的读书会是什么时候？—— 查询商城订单并给出场次时间与入场凭证指引。

## 依赖与前置条件

- 运行环境：Python 3（脚本仅使用标准库）
- 外部依赖：麦当劳 MCP Server，地址与鉴权见上文
- 服务限制：每令牌每分钟 600 次请求，超限返回 429；令牌无效返回 401

## 已知边界

- 一期不纳入积分兑换类活动，避免与派对下单链路混淆。
- 售罄活动只做提示，不支持预约提醒。
- 不支持并发下单，多个活动必须串行。
- 活动日历与商品之间没有直接 ID 关联，只能语义匹配；匹配不确定时降级为资讯展示。
- 门店、日期、场次与商品详情的返回字段名已实测确认并写入工具契约文档；脚本消费规范化上下文，锁定键缺失时会显式报错而不是猜测。
- 后端对已过下架时间的商品仍返回上架状态，因此可预订判定叠加了有效期窗口，两点同时成立才会被展示为可预订。
- 同名价格字段单位不一致：商品与 SKU 为元，场次为分。场次价格展示前须换算为元，脚本对疑似分口径的数值会给出单位告警。
